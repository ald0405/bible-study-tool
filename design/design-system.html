Design System

The app already has a deliberate color and type system — a navy accent, a warm neutral background, Source Serif 4 for reading, IBM Plex Sans/Mono for interface and data. What it's missing is a formal scale for radius, shadow, and selected-state styling — every box, button and badge currently hardcodes its own one-off value. This page proposes the missing scale, documents the full token set, and shows it applied to the three places that currently read as flat or ambiguous: the search button, the sidebar panels, and "selected" feedback across verses, discourse markers and cross-references.

Scope: this is a reference artifact only. No file under static/ has been touched — style.css, index.html and app.js are exactly as they were. Rolling an approved direction into the real app is a separate next step, once this has been reviewed.

03

Radius new

Replaces the current 2–5px one-offs

Today border-radius is set independently on every rule — 2px, 3px, 4px, 5px, scattered with no relationship to each other. This is the proposed scale that replaces all of them.

--r-sm6px

Badges & small chips — verse badge, quote badge, bar tracks

--r-md9px

Buttons & inputs — search bar, example chips

--r-lg14px

Cards & panels — sidebar boxes, reading grid wrap, minimap

--r-pill999px

Fully-rounded tags, kept distinct from --r-sm so "pill" is a deliberate choice, not a side effect

04

Shadow new

The app currently has none

Zero panels or buttons currently cast a shadow. These two are soft and derived from --text (the app's own ink color) rather than a generic black, so they stay inside the existing warm/neutral palette.

--shadow-sm

Resting elevation — panels, buttons

--shadow-md

Hover / elevated state

--shadow-drawer

Directional only — the cross-ref drawer's existing cast, named but not folded into the general scale

05

Selected state new

One pattern, used everywhere

Right now three different mechanisms each render "selected" differently — a plain background tint on verse cells, an untokenized hex on term rows, the yellow highlight color reused on Who Acts lemmas — and most list rows (discourse markers, cross-refs, summary rows) have no selected state at all, only hover. The one place this already works well is .glossary-entry.active: a background tint plus an inset ring. This generalizes that into two shared tokens, applied consistently everywhere.

09 · Open decision

How rounded should buttons and inputs be?

The reference you pointed to (your own "Nadia UI Kit") uses fully pill-shaped, 999px buttons. This document instead proposed a moderate --r-md (9px) for buttons and inputs — closer to this app's scholarly, text-dense character than a fully pill-shaped control. Rather than settle that by description, here are all three, live, on the real search button. Pick one and the rest of this system follows.

Current — 3px
Proposed — 9px
Pill — 999px
